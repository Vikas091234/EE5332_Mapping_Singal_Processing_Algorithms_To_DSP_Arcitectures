# EE5332 — Mapping Signal Processing Algorithms to DSP Architectures

Coursework and project work from **EE5332 at IIT Madras**, focused on mapping signal-processing algorithms to FPGA/DSP-oriented hardware architectures using RTL, C/C++, Vitis HLS, Vivado, AXI interfaces, and PYNQ.

The repository contains five laboratory assignments and a course project implementing and evaluating streaming 2D convolution accelerators.

## Repository contents

- **`labs/`** — EE5332 laboratory assignments (Labs 1–5)
- **`project/`** — 2D convolution accelerator project
- **`README.md`** — repository overview
- **`REPORT.md`** — coursework/project summary
- **`.gitignore`** — ignores selected Vitis/Vivado-generated files

> The uploaded coursework contains both source files and generated tool artifacts such as synthesis reports, HLS/Vivado project data, logs, and exported hardware files. The tree below therefore shows the **source/relevant organization**, rather than every autogenerated file.

# Labs

## Lab 1 — RTL / SystemVerilog basics

Lab 1 contains four RTL exercises with corresponding test benches:

- counter
- extend-and-negate arithmetic/sign extension
- sequence detector
- shift register

The `lab1/lab1/` directory contains the submitted-style RTL and testbench files.

The repository also contains `dsdlabs-main/`, which provides additional FPGA-oriented examples covering counters, FPGA counters, pin constraints, and multiplier/timing material.

The lab instructions specify simulation using **Icarus Verilog (`iverilog`)**.

## Lab 2 — FIR filter in C

Lab 2 implements a FIR filtering kernel in C and uses Python to generate the coefficients and reference test vectors.

Main files:

- `fir.c`, `fir.h` — FIR implementation
- `fir_tb.c` — C test bench
- `generate_fir_test_vectors.py` — coefficient/test-vector generation
- `Makefile` — build/test flow

The lab README specifies a **51-tap low-pass FIR** using a windowed-sinc/Hamming coefficient-generation flow.

## Lab 3 — Vitis HLS basics

Lab 3 applies Vitis HLS directives to a differential-equation solver.

The submitted material contains:

- `diffeq.cpp`
- four directive Tcl files
- four synthesis reports
- `lab3.pdf`
- supporting screenshots

The assignment explores different combinations of pipelining, multiplier constraints, initiation interval, and timing constraints.

## Lab 4 — FIR filter synthesis

Lab 4 takes the FIR filter into Vitis HLS synthesis.

The assignment explores:

1. default synthesis,
2. directive-based optimization targeting **II = 1** and improved operating frequency,
3. a maximum-multiplier constraint.

AXI-Stream interfaces are also part of the synthesis setup.

The directory contains the FIR source/testbench, coefficient and test-vector files, four directive/report sets, images, and the submitted PDF analysis.

## Lab 5 — Streaming FIR on PYNQ

Lab 5 compares two hardware-interface approaches for a **21-tap low-pass FIR**:

- **MMIO / AXI-Lite** — CPU-controlled, single-sample interaction
- **DMA / AXI-Stream** — bulk streaming transfer

The HLS directory contains separate streaming and MMIO implementations and test benches. The Vivado directory contains the block-design creation script, while the PYNQ directory contains the notebook/script and generated `.bit`/`.hwh` hardware files.

The lab also investigates:

- pipeline and unroll directives,
- resource usage,
- floating-point versus fixed-point representation,
- DMA versus MMIO performance,
- AXI Timer measurements.

# Course Project — 2D Convolution Accelerator

The main project implements a **K×K 2D convolution accelerator** for grayscale/RGB image data using an FPGA-oriented streaming architecture.

The central architecture uses:

- row-wise streaming through **AXI-Stream**,
- a **line buffer** for spatial data reuse,
- a **sliding window** for convolution,
- HLS pipelining and loop unrolling,
- floating-point and fixed-point datapaths,
- AXI/DMA integration,
- PYNQ hardware validation against a NumPy/SciPy software reference.

## Design points

Five design points are present in the project:

| # | Directory | Configuration |
|---|---|---|
| 01 | `01_baseline_no_pragma` | Streaming 3×3 baseline, float, unpartitioned |
| 02 | `02_float_pipelined_3x3` | Pipelined/unrolled floating-point 3×3 |
| 03 | `03_fixed_pipelined_3x3` | Fixed-point 3×3 using `ap_fixed<16,3>` |
| 04 | `04_float_pipelined_5x5` | Floating-point 5×5 streaming convolution |
| 05 | `05_generalized_multichannel` | Runtime-configurable multichannel convolution |

The exact implementation details are kept inside each design-point directory rather than being presented as if all five directories have identical file layouts.

### Design-point contents

Depending on the design point, the directory may contain:

- HLS C/C++ source and headers
- Vitis HLS project files
- synthesis reports
- exported HLS IP
- PYNQ deployment notebooks/scripts
- `.bit` bitstreams
- `.hwh` hardware handoff files
- test images
- Vivado projects
- screenshots and notebook PDF exports

The project README specifically identifies `UPLOAD FILES` / `UPLOAD_FILES` directories as deployment bundles for PYNQ in the applicable design points.

## Generated files

Vitis HLS and Vivado generate a large amount of intermediate data. The uploaded coursework contains some of these generated artifacts, including synthesis/implementation data, logs, caches, and exported IP files.

The repository `.gitignore` is configured to ignore several Vitis-generated artifacts and logs, including `.autopilot/`, `.apc/`, `*.log`, `*.jou`, `solution1/`, and related generated files.

For a clean Git repository, source code, reports, notebooks, deployment files, and selected synthesis results should be preferred over committing complete generated HLS/Vivado build trees.
